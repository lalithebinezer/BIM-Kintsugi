### 👩🏻🏫 Component ABC

All components are built on a common set of rules to keep the ecosystem compatible and extensible.

## 📏 Code Guidelines

To keep document page rendering clean and releases smooth, follow these rules:

### 1. 📝 JSDoc Rules
* **1.1 Single-Line Summaries**: The summary of every exported class, interface, function, type, or const must be a single line. Additional content should go into constructors or parameters.
  ```typescript
  // ✅ Good
  /** Manages block insertions across all drawings. */
  export class BlockAnnotations { ... }
  ```
* **1.2 No Fenced Code Blocks inside `@param`**: Fenced code blocks inside `@param` render improperly in tables. Use plain prose or place code blocks under `@example`.
* **1.3 Escape Literal Braces**: Wrap literal curly braces `{ ... }` or TypeScript generics `Map<string, number>` in backticks so they are parsed cleanly as literal code text.

### 2. 🌐 Example File Rules
* **Absolute github.io URLs**: All `fetch` calls in examples must use absolute URLs pointing to `github.io` (e.g. `https://thatopen.github.io/engine_components/resources/...`), not relative paths.
* **Commit Resources**: If adding a new resource file, commit the resource file to the repository's `resources/` folder.

### 3. 🧱 Third-Party Libraries
* **Sync Web-IFC and WASM**: When bumping `web-ifc` version in `package.json`, update all corresponding unpkg WASM references in your examples to match.

### 4. 📊 Chart & HTML Theme Rules
* **Positive-Only Pie Data**: Pie, doughnut, and polarArea charts must only use positive random values.
* **Default Themes**: Set default borderColor to transparent (`#00000000`) for dark theme charts. Ensure `example.html` specifies `class="bim-ui-dark"`.

## 🛠️ Creating Custom Components

Our libraries are extensible, meaning you can easily create your own custom components to cover specific project requirements.

### 📝 Basic Class Structure
To create a custom component, create a class that extends `OBC.Component`. Here is a basic "Hello World" component:

```typescript
import * as OBC from "@thatopen/components";

/** A basic component to say hello in the console. */
export class HelloWorldComponent extends OBC.Component {
  // A static UUID (v4) that uniquely identifies it
  static readonly uuid = "60bd6763-f9ff-4820-a04f-2054922c0297" as const;

  enabled = true;
  private readonly _message = "Hello";

  constructor(components: OBC.Components) {
    super(components);
    // Register this instance with components manager
    components.add(HelloWorldComponent.uuid, this);
  }

  greet(name: string) {
    const message = `${this._message} ${name}!`;
    console.log(message);
  }
}
```

### 🌍 Global Availability
Components are registered within the `Components` manager instance, ensuring they are unique and globally available. To access a component anywhere else in your application, retrieve it via `get()`:

```typescript
// Always get components using the get method to avoid duplicate instantiations
const hwComponent = await components.get(HelloWorldComponent);
```

### ♻️ Lifecycle Management
You can hook into the viewer's lifecycle hooks to automatically update logic or release memory:

* `OBC.Updateable`: Automatically runs `update(delta)` every frame.
* `OBC.Disposable`: Releases memory when the viewer application is disposed.

```typescript
import * as THREE from "three";
import * as OBC from "@thatopen/components";

/** A component showing update and dispose lifecycles. */
export class HelloWorldComponent extends OBC.Component
  implements OBC.Disposable, OBC.Updateable {
  static readonly uuid = "0f89b34b-fc6b-4b97-b56d-1edeb0a308a2";

  readonly onAfterUpdate = new OBC.Event();
  readonly onBeforeUpdate = new OBC.Event();
  readonly onDisposed = new OBC.Event();

  enabled = true;
  someMesh = new THREE.Mesh();
  private readonly _message = "Hello";

  constructor(components: OBC.Components) {
    super(components);
    components.add(HelloWorldComponent.uuid, this);
  }

  greet(name: string) {
    console.log(`${this._message} ${name}!`);
  }

  dispose() {
    this.enabled = false;
    this.onBeforeUpdate.reset();
    this.onAfterUpdate.reset();
    
    // Clean up Three.js geometry/materials
    const disposer = this.components.get(OBC.Disposer);
    disposer.destroy(this.someMesh);
    
    this.onDisposed.trigger();
    this.onDisposed.reset();
  }

  async update(delta?: number) {
    this.onBeforeUpdate.trigger();
    console.log("Updated! Delta: " + delta);
    this.onAfterUpdate.trigger();
  }
}
```

### 🎨 UI Decoupling
Keep UI styling and element code decoupled from your component logic. Components should handle data and scene calculations, while our UI components library handles rendering the UI blocks.

## 🧼 Keeping Components Clean & Efficient

Follow these coding standards and memory safety patterns to ensure performance and prevent resource leaks.

### 🗃️ Folder Structure
Always name the entry file of your component `index.ts` and store it in a folder matching the component's name. If you have supporting files, create a nested `src/` folder:
```
MyComponent/
├── index.ts
└── src/
    ├── supporting-file-1.ts
    ├── supporting-file-2.ts
    └── index.ts (exporting all public elements)
```

### 🧼 TypeScript Guidelines
* **Naming**: Prefix private members with an underscore (e.g. `_components`).
* **Avoid `!` Assertions**: If a property is not initialized in the constructor, use `?` or create a getter with an error fallback check:
  ```typescript
  private _customProperty?: string;

  get customProperty(): string {
    if (!this._customProperty) {
      throw new Error("Custom property not initialized!");
    }
    return this._customProperty;
  }
  ```
* **Explicit Private Properties**: Never define private properties directly in the constructor signature. Declare them explicitly beforehand:
  ```typescript
  // ✅ Correct
  private _components: Components;
  constructor(components: Components) {
    this._components = components;
  }
  ```
* **Readonly Events**: Always make event triggers `readonly` and initialize them directly:
  ```typescript
  readonly onCreated = new OBC.Event<number>();
  ```

### 🧠 Memory Management & Garbage Collection
Memory leaks can cause WebGL environments to crash. Ensure you clean up resources properly when your component is disposed:

#### 1. 🥎 3D Objects & Meshes
Three.js requires manual deletion of geometries and materials. Use the `Disposer` component to clean up assets and empty arrays to release references:
```typescript
class YourComponent extends Component implements Disposable {
  readonly onDisposed = new OBC.Event();
  private _meshes: THREE.Mesh[] = [];

  dispose() {
    const disposer = this.components.get(OBC.Disposer);
    for (const mesh of this._meshes) {
      disposer.destroy(mesh); // disposes geometries and materials
    }
    this._meshes = []; // Clear array references so GC can collect them
    this.onDisposed.trigger();
    this.onDisposed.reset();
  }
}
```

#### 2. 📅 Global & External Event Listeners
If you bind event listeners to the global `window` object or elements outside your component, use a `setupEvents` helper to clean them up:
```typescript
class YourComponent extends Component implements Disposable {
  constructor(components: Components) {
    super(components);
    this.setupEvents(true);
  }

  dispose() {
    this.setupEvents(false);
  }

  private setupEvents(active: boolean) {
    if (active) {
      window.addEventListener("mousemove", this.logMessage);
    } else {
      window.removeEventListener("mousemove", this.logMessage);
    }
  }

  private logMessage = () => {
    console.log("Mouse moved");
  };
}
```

#### 3. 🐘 Data Arrays and Objects
For heavy data structures, release memory quickly by resetting them:
```typescript
dispose() {
  this.dataArray = [];
  this.dataObject = {};
}
```

## 👾 The Fragments Schema
Flatbuffers requires defining data schemas as `.fbs` text files. Below is the structure of the Fragments format schema.

### 🧩 The Model Table
The main object and entry point of all Fragment files. Each file contains a single `Model` structure:
```flatbuffers
table Model {
    metadata: string; // JSON string for generic metadata (e.g., {"schema":"IFC4"})
    guids: [string] (required); // Global Unique Identifiers of elements
    guids_items: [uint] (required); // Index mapping localIds to guids
    max_local_id: uint; // Next localID available for serialization
    local_ids: [uint] (required); // File-specific identification for each item
    categories: [string] (required); // Array of IFC categories found in the file
    meshes: Meshes (required); // explicit geometries container
    unique_attributes: [string]; // Deduplicated list of item attributes
    attributes: [Attribute]; // Data fields stored as array-of-arrays
    relation_names: [string]; // Deduplicated relation identifiers
    relations: [Relation]; // Relations array-of-arrays
    relations_items: [int]; // Index mapping localIds to relations
    guid: string (required); // Global ID identifying this model uniquely
    spatial_structure: SpatialStructure; // Spatial hierarchy tree
}
```

### 🪑 Meshes, Samples & Representations
Geometries are stored in the `Meshes` table. To reuse geometries, instances are created as `Samples`:
```flatbuffers
table Meshes {
    coordinates: Transform (required); // Global coordinates
    meshes_items: [uint] (required); // Maps localId index to meshes
    samples: [Sample] (required); // Instances of geometries in the model
    representations: [Representation] (required); // Geometry bounding box and class (Shell, CircleExtrusion)
    materials: [Material] (required); // Unique colors and sidedness
    circle_extrusions: [CircleExtrusion] (required); // Wire with thickness (e.g., rebars)
    shells: [Shell] (required); // Brep geometries (exterior profiles and holes)
    local_transforms: [Transform] (required); // Local instance offsets
    global_transforms: [Transform] (required); // Global element transforms mapped by meshes_items
}
```
* **Circle Extrusions**: Specifically optimized for modeling reinforcement bars (rebars).
* **Shell Types**: Categorized into *Default* (under 65,535 points) and *Big* (over 65,535 points) to keep memory footprint compact.

### 🌳 Spatial Structure
A recursive tree structure that groups items together under spatial nodes (e.g., project, site, storeys):
```flatbuffers
table SpatialStructure {
    local_id: uint = null; // Node local ID
    category: string; // Node category name (e.g. "IFCBUILDINGSTOREY")
    children: [SpatialStructure]; // Nested child nodes
}
```

## 🛠️ Building Your Own Exporter/Importer
Since Fragments is based on Flatbuffers, you can compile and generate importers/exporters for other technology stacks (Python, C#, C++, Rust, etc.).

### 🤖 How to Compile the Schema
1. Download the [Fragments schema file](https://docs.thatopen.com/components/tutorial-paths).
2. Download the `flatc` compiler executable from the [Flatbuffers releases page](https://github.com/google/flatbuffers/releases).
3. Compile the `.fbs` schema for your target programming language:
   ```bash
   # Example: compile for C++
   flatc --cpp fragments.fbs
   
   # Example: compile for Python
   flatc --python fragments.fbs
   ```

### ⬇️ Reading and Writing Fragments
* **Importing**: Load the compiled `.frag` files. Note that some production files are GZIP compressed and must be decompressed before flatbuffers parsing.
* **Exporting**: Follow the flatbuffers builder APIs to assemble `Model` tables. Refer to our open-source TypeScript exporters:
  * [IFC-to-Fragment Exporter Geometry Class](https://github.com/ThatOpen/engine_fragment)
  * [Property Sets Exporter Class](https://github.com/ThatOpen/engine_fragment)

```typescript
import * as THREE from "three";
import * as OBC from "@thatopen/components";

const container = document.getElementById("container")!;

// 1. Initialize Components manager
const components = new OBC.Components();

// 2. Setup the World (Scene, Camera, Renderer)
const worlds = components.get(OBC.Worlds);
const world = worlds.create<
  OBC.SimpleScene,
  OBC.SimpleCamera,

const material = new THREE.MeshLambertMaterial({ color: "#6528D7" });

world.scene.three.add(cube);

// Setup lights and grid
world.scene.setup();

// Orient the camera view
world.camera.controls.setLookAt(3, 3, 3, 0, 0, 0);
```

## 💬 Communicating via BCF (BIM Collaboration Format)
BIM teams use BCF to communicate issues, clashes, and queries. A BCF topic bundles metadata, comments, and viewport camera angles so that issues are not disconnected from the 3D model geometry.

### 🚀 BCF Setup & Configuration
Get the `BCFTopics` component to coordinate issue definitions:
```typescript
const bcfTopics = components.get(OBC.BCFTopics);
bcfTopics.setup({
  author: "developer@example.com",
  types: new Set([...bcfTopics.config.types, "Information", "Coordination"]),
  statuses: new Set(["Active", "In Progress", "Done", "In Review", "Closed"]),
  users: new Set(["team-member@example.com"]),
  version: "3", // BCF version standard
});
```

### 📡 Creating and Updating Topics
Create topics to track problems, add comments, and link viewpoints dynamically:
```typescript
// 1. Create a BCF Topic
const topic = bcfTopics.create({
  title: "Missing column support",
  description: "Structural elements are badly defined.",
  dueDate: new Date("2026-12-31"),
  type: "Clash",
  priority: "Major",
  stage: "Design",
  labels: new Set(["Structure", "Coordination"]),
  assignedTo: "team-member@example.com",
});

// 2. Add comments
const comment = topic.createComment("Should we add a brace here?");

// 3. Reactively update properties (triggers UI update events)
topic.set({ title: "Resolved Column Support" });
```

### 🤝 Event Linkages (Viewpoints)
Link viewpoints automatically upon topic creation to store precise camera angles:
```typescript
const viewpoints = components.get(OBC.Viewpoints);

bcfTopics.list.onItemSet.add(async ({ value: topic }) => {
  const viewpoint = viewpoints.create();
  viewpoint.world = world;

  // Link using the viewpoint GUID to avoid memory leaks
  topic.viewpoints.add(viewpoint.guid);
});
```

### ⏬ Importing and Exporting BCF Archives
BCF archives are compressed `.bcf` (ZIP) files:
```typescript
// Export BCF
const exportBCF = async () => {
  const bcfBuffer = await bcfTopics.export();
  const bcfFile = new File([bcfBuffer], "issues.bcf");
  
  const a = document.createElement("a");
  a.href = URL.createObjectURL(bcfFile);
  a.download = bcfFile.name;
  a.click();
};

// Import BCF
const loadBCF = async (buffer: Uint8Array) => {
  const { topics, viewpoints } = await bcfTopics.load(buffer);
  console.log("Loaded Topics:", topics);
};
```

## 📦 Working with Bounding Boxes (BoundingBoxer)
Measuring coordinate extents and fitting the camera to loaded geometry is simplified using the `BoundingBoxer` component.

### 📐 Boxer Setup & Model Boundaries
Retrieve the `BoundingBoxer` and calculate the overall boundings of all loaded models:
```typescript
const boxer = components.get(OBC.BoundingBoxer);

const getLoadedModelsBoundings = () => {
  boxer.list.clear(); // Clear previous boxes
  boxer.addFromModels(); // Accumulate loaded models
  const box = boxer.get();
  boxer.list.clear();
  return box;
};
```

### 🔍 Category and Selection Focus
Fit camera boundings to specific model selections using a `ModelIdMap`:
```typescript
const getByCategory = async (category: string, modelId: string) => {
  const model = fragments.list.get(modelId);
  if (!model) return null;

  const items = await model.getItemsOfCategories([new RegExp(`^${category}$`)]);
  const localIds = Object.values(items).flat();

  // Define selection map
  const modelIdMap: OBC.ModelIdMap = { [modelId]: new Set(localIds) };

  boxer.list.clear();
  await boxer.addFromModelIdMap(modelIdMap);
  const box = boxer.get();
  boxer.list.clear();
  return box;
};
```

### 🔄 Orthographic Camera Orientations
Set the camera view automatically based on standard model bounding box orientations:
```typescript
const viewFromOrientation = async (
  orientation: "front" | "back" | "left" | "right" | "top" | "bottom"
) => {
  const camera = world.camera;
  if (!camera.hasCameraControls()) return;

  const { position, target } = await boxer.getCameraOrientation(orientation);
  await camera.controls.setLookAt(
    position.x, position.y, position.z,
    target.x, target.y, target.z,
    true // Animate transition
  );
};
```

### 📦 Box Visualizers and Helpers
Add bounding box outline helpers to the Three.js scene:

```typescript
let helpers: THREE.Box3Helper[] = [];

const createBoxHelper = (box: THREE.Box3) => {
  const helper = new THREE.Box3Helper(box);
```

### 🖱️ Calculating Slope Normals on Click
Perform raycast intersections against 3D surface meshes, extract face normals, and add slope annotation arrows to the drawing plane:
```typescript
container.addEventListener("click", async () => {
  const hit = await caster.castRay();
  if (!hit?.normal) return;

  const worldNormal = hit.normal;

  // A near-zero horizontal normal projection means a flat surface
  const run = Math.sqrt(worldNormal.x ** 2 + worldNormal.z ** 2);
  if (run < 1e-6) return;

  const yAbs = Math.abs(worldNormal.y);
  if (yAbs < 1e-6) return; // Vertical surface

  // Compute slope ratio
  const slope = run / yAbs;

  // Calculate downhill flow vector projection
  const direction = new THREE.Vector3(worldNormal.x, 0, worldNormal.z).normalize();

  // Map hit point back to local drawing space coordinates
  const position = drawing.three.worldToLocal(hit.point.clone());
  position.y = 0;

  // Stamp slope arrow annotation
  slopes.add(drawing, { position, direction, slope, style: "percentage" });
});
```

## ⚡ Synchronous Snapping Performance (GraphicVertexPickerMode)
By default, snapping utilizes asynchronous raycasts. For dense models, pre-generating meshes enables fast synchronous snapped picks.

### 🚀 Synchronous Snapping Config
Construct picking meshes from fragment buffers and register them with the world:
```typescript
const meshes: THREE.Mesh[] = [];

for (const [, model] of fragments.list) {
  const ids = await model.getItemsIdsWithGeometry();
  const geometryData = await model.getItemsGeometry(ids);

  for (const itemId in geometryData) {
    for (const geom of geometryData[itemId]) {
      const geometry = new THREE.BufferGeometry();
      geometry.setAttribute("position", new THREE.Float32BufferAttribute(geom.positions, 3));
      geometry.setIndex(Array.from(geom.indices));

      const mesh = new THREE.Mesh(geometry);
      mesh.applyMatrix4(geom.transform);
      mesh.applyMatrix4(model.object.matrixWorld);
      
      meshes.push(mesh);
    }
  }
}

// Enable synchronous vertex snapping
const enableSynchronousSnapping = (enable: boolean) => {
  if (enable) {
    measurer.pickerMode = OBF.GraphicVertexPickerMode.SYNCHRONOUS;
    measurer.delay = 0;
    
    // Add meshes to active world snapping collection
    for (const mesh of meshes) world.meshes.add(mesh);
  } else {
    measurer.pickerMode = OBF.GraphicVertexPickerMode.DEFAULT;
    for (const mesh of meshes) world.meshes.delete(mesh);
  }
};
```

### 🕹️ Custom State Machine Event Handling

```typescript
type CrossMarkerState = { kind: "awaitingPoint"; preview: THREE.Vector3 | null };

type CrossMarkerEvent =
  | { type: "MOUSE_MOVE"; point: THREE.Vector3; drawing?: OBC.TechnicalDrawing }
  | { type: "CLICK";      point: THREE.Vector3; drawing?: OBC.TechnicalDrawing }
  | { type: "ESCAPE" };

function crossMarkerMachine(
  state: CrossMarkerState,
  event: CrossMarkerEvent
): CrossMarkerState {
  switch (state.kind) {
    case "awaitingPoint": {
      if (event.type === "MOUSE_MOVE") {
        return { kind: "awaitingPoint", preview: event.point.clone().setY(0) };
      }
      if (event.type === "ESCAPE") {
        return { kind: "awaitingPoint", preview: null };
      }
      return state;
    }
  }
}
```

### ✍️ Custom AnnotationSystem Subclass
Extend the abstract class and implement the state machine interfaces, custom geometric representations, and handle picking calculations:
```typescript
class CrossMarkers
  extends OBC.AnnotationSystem<CrossMarkerSystem>
  implements OBC.Transitionable<CrossMarkerState, CrossMarkerEvent>, OBC.Disposable
{
  enabled = true;
  machineState: CrossMarkerState = { kind: "awaitingPoint", preview: null };
  readonly onMachineStateChanged = new OBC.Event<CrossMarkerState>();

  constructor(components: OBC.Components) {
    super(components);
    this.styles.set("default", { color: 0xff6600, textOffset: 0, fontSize: 0, lineSize: 0.25 });
  }

  // 1. Send input signals to state machine
  sendMachineEvent(event: CrossMarkerEvent): void {
    const eventDrawing = (event as { drawing?: OBC.TechnicalDrawing }).drawing ?? null;
    if (eventDrawing) this._previewDrawing = eventDrawing;

    if (event.type === "CLICK" && this._previewDrawing) {
      this.add(this._previewDrawing, { position: event.point.clone().setY(0) });
    }

    const next = crossMarkerMachine(this.machineState, event);
    if (next !== this.machineState) {
      this.machineState = next;
      this._updatePreview();
      this.onMachineStateChanged.trigger(this.machineState);
    }
  }

  // 2. Build committed Three.js geometries
  protected _buildGroup(marker: CrossMarker, style: CrossMarkerStyle): THREE.Group {
    const { x, z } = marker.position;
    const s = style.lineSize;
    const positions = new Float32Array([
      x - s, 0, z,     x + s, 0, z,     // horizontal segment
      x,     0, z - s, x,     0, z + s, // vertical segment
    ]);
    const geo = new THREE.BufferGeometry();
    geo.setAttribute("position", new THREE.BufferAttribute(positions, 3));
    const ls = new THREE.LineSegments(geo, this._getMaterial(marker.style));
    ls.userData.isDimension = true;
    ls.layers.set(1);
    
    const group = new THREE.Group();
    group.add(ls);
    return group;
  }

  // 3. Simple distance raycast to pick center of cross handles
  pickHandle(
    drawing: OBC.TechnicalDrawing,
    ray: THREE.Ray,
    threshold = 0.15
  ): { uuid: string; handle: never } | null {
    for (const [uuid, entry] of drawing.annotations) {
      if (entry.system !== (this as any)) continue;
      const marker = entry.data as CrossMarker;
      const worldPos = drawing.three.localToWorld(marker.position.clone());
      if (ray.distanceToPoint(worldPos) < threshold) {
        return { uuid, handle: null as never };
      }
    }
    return null;
  }

  protected _onDispose(): void {
    this.onMachineStateChanged.reset();
  }
}
```

```typescript
  const result: Record<string, Record<string, any>> = {};

  for (const pset of rawPsets) {
    const { Name: psetName, HasProperties } = pset;
    if (!("value" in psetName && Array.isArray(HasProperties))) continue;
    const props: Record<string, any> = {};

    for (const prop of HasProperties) {
      const { Name, NominalValue } = prop;
      if (!("value" in Name && "value" in NominalValue)) continue;
      props[Name.value] = NominalValue.value;
    }
    result[psetName.value] = props;
  }
  return result;
};
```

```typescript
// Generate Cubic UV Projection Coordinates
const projectCubicUVs = (geometry: THREE.BufferGeometry) => {
  const indexArray = geometry.index!.array;
  const positions = geometry.attributes.position!.array!;
  const normals = geometry.attributes.normal!.array!;
  const uvArray = new Float32Array((positions.length / 3) * 2);

  for (let i = 0; i < indexArray.length; i++) {
    const index = indexArray[i];
    const x = positions[index * 3];
    const y = positions[index * 3 + 1];
    const z = positions[index * 3 + 2];
    const nx = Math.abs(normals[index * 3]);
    const ny = Math.abs(normals[index * 3 + 1]);
    const nz = Math.abs(normals[index * 3 + 2]);

    if (nx > ny && nx > nz) {
      uvArray[index * 2] = y;
      uvArray[index * 2 + 1] = z;
    } else if (ny > nx && ny > nz) {
      uvArray[index * 2] = x;
      uvArray[index * 2 + 1] = z;
    } else {
      uvArray[index * 2] = x;
      uvArray[index * 2 + 1] = y;
    }
  }
  geometry.setAttribute("uv", new THREE.BufferAttribute(uvArray, 2));
};
```

## ?? Navigating your 3D Scene with the ViewCube

Users navigating a 3D BIM scene lose track of orientation as they orbit and pan � without a reference indicator, recovering a specific view like front or top requires manual camera adjustments. The ViewCube is a compact 3D orientation indicator that stays in sync with the camera and lets users snap to predefined views by clicking its faces. This tutorial covers creating a basic 3D world with scene, camera, and renderer; placing the ViewCube inside the viewport element and linking it to the camera; keeping it synchronized by calling the orientation update on every camera control event; and handling a face click event to reposition the camera to a specific look-at target with animation.

### Event\<T\>

Simple, typed event handler. Callbacks can be synchronous lambdas or arrow functions. To remove a specific handler later, declare the callback as a named object reference.

### TechnicalDrawing

The **core spatial aggregate** for a single technical drawing � combines a Three.js container group, viewport collection, layer manager, and annotation store.

**Key concept:** The drawing lives in the local **XZ plane** (Y = 0) and projects geometry along its local **-Y axis**. All 2D content must be added as children of `drawing.three` to inherit its world transform.

```ts
const techDrawings = components.get(OBC.TechnicalDrawings);
const drawing = techDrawings.create(world);

// Orient to a standard view
drawing.orientTo(new THREE.Vector3(0, -1,  0)); // top / plan
drawing.orientTo(new THREE.Vector3(0,  0, -1)); // front elevation
drawing.orientTo(new THREE.Vector3(-1, 0,  0)); // right elevation

// Set projection depth
drawing.far = 20;

// Create layers before projecting
drawing.layers.create("visible", { material: new THREE.LineBasicMaterial({ color: 0x000000 }) });
drawing.layers.create("hidden",  { material: new THREE.LineDashedMaterial({ color: 0x888888, dashSize: 0.2, gapSize: 0.1 }) });

// Project BIM items onto the drawing
await drawing.addProjectionFromItems(modelIdMap, {
  layers: { visible: "visible", hidden: "hidden" },
  onProgress: (msg, pct) => console.log(msg, pct),
});

// Add pre-built LineSegments with BVH picking
drawing.addProjectionLines(myLineSegments, "visible");

// Project arbitrary world-space LineSegments to drawing space
const projected = TechnicalDrawing.toDrawingSpace(worldLines, drawing);
drawing.three.add(projected);

// Raycast against the drawing (for annotation placement)
const hit = drawing.raycast(worldRay, viewport);
if (hit) console.log("hit at drawing-local point:", hit.point);

// Align drawing to a real-world plane using 3-point correspondences
drawing.alignTo(drawingPts, worldPts);

// Dispose
drawing.dispose();
```

### TechnicalDrawings

OBC `Component` that **creates and manages `TechnicalDrawing` instances**. The single entry point for all 2D drawing work in the engine.

**Extends:** `Component`  **Implements:** `Disposable`  
**UUID:** `"5c7d3b9a-4e8f-4a2b-9c1d-0e3f2a5b7c8d"`

```ts

// 2. Register annotation systems (global singletons)

const leaders = techDrawings.use(OBC.LeaderAnnotations);
const slopes  = techDrawings.use(OBC.SlopeAnnotations);

// 5. Set up layers

  material: new THREE.LineBasicMaterial({ color: 0x000000 }),
});
drawing.layers.create("hidden", {
  material: new THREE.LineDashedMaterial({ color: 0x999999, dashSize: 0.2, gapSize: 0.1 }),
});

// 6. Project BIM geometry

  layers: { visible: "visible", hidden: "hidden" },
});

// 8. Add dimensions interactively (state machine)
dims.send(drawing, "start", { point: p1 });
dims.send(drawing, "setEnd", { point: p2 });
dims.send(drawing, "commit", { offset: 0.5 });
```
